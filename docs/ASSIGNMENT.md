# T06 · 플랜두씨 다이어리 1 — 내 계획과 실제를 담는 앱

출처: 사용자가 제공한 과제 번호·제목·기록 주제, [공식 T06 과제 화면](https://aleph-omega.vercel.app/cortex?panel=tasks), [공식 학생용 공통 매뉴얼](https://aleph-omega.vercel.app/manual/student-free) v6 · 2026-09-18, 상위 공통 가이드.

기존 인증된 Codex 내장 브라우저에서 T06 전체 설명과 카드 1~5의 기준을 확인했다. 아래는 확인된 내용의 작업용 정리이며 구현·검증·제출 완료 기록이 아니다. 확인한 코드만 표시하며 C01~C83 전체 번호 목록으로 추정하지 않는다.

## 사용자가 정한 기록 주제

**ALEPH 공부·과제 진행**. 이후 사용자가 이전 과제 근거를 추천해 가져오도록 요청하고 추천안을 승인했다. 출처와 승인값은 [RECOMMENDED-RECORDS.md](RECOMMENDED-RECORDS.md), [승인 정본](../records/user-approved-recommendation.json)을 따른다. 실제 기록·사용자 판단을 임의로 만들지 않는다.

## Plan과 수정 이력

- 계획은 ID, 기간, 우선순위, 성공 기준, 예상 시간을 가진다. 시간 단위는 구현 시 명시하고 저장·표시·집계에서 같게 유지한다. 분 단위로 통일하는 것은 구현 제안이며 과제 화면이 지정한 단위는 아니다.
- 같은 Plan ID의 수정 이력을 남기며 이전 이력을 덮어쓰지 않는다. (C04~C08)
- 사용자의 계획 자료와 실제 행동을 분리한다.

## 할 일과 완료 처리

- 할 일 생성·조회·수정·삭제, 완료·다시 열기를 제공한다.
- 마감일, 우선순위, 태그, 예상 시간을 다룬다. 필드의 영문 이름은 실제 구현에서 정한다.
- 검색·필터·안정적인 정렬을 제공하고 동률 처리 규칙도 표시한다. (C09~C20)
- 완료 요청을 두 번 반복해도 완료 기록은 하나만 남고 See 완료 수는 한 번만 증가해야 한다.
- 요청 키와 DB 고유 제약으로 완료 중복을 막는다. (C21~C22)

## 실행 기록

- 할 일별 실행 기록에 시작·종료 시각, 실제 소요 시간, 막힌 이유를 남긴다.
- 실행 기록을 추가해도 Plan을 덮어쓰지 않는다. (C23~C27)

## See 집계와 다음 계획

선택한 계획의 기간을 기준으로 다음을 계산한다.

| 항목 | 확인된 계산 규칙 |
|---|---|
| 전체 할 일 | 삭제되지 않은 할 일 수 (C28) |
| 완료 | 현재 완료 상태인 할 일 수 (C29) |
| 지연 | 완료되지 않았고 due_date가 Asia/Seoul 기준 오늘보다 이전인 할 일 수 (C30) |
| 막힘 | 실행 기록 중 비어 있지 않은 막힌 이유가 하나 이상 있는 할 일 수 (C31) |
| 예상 시간 | 현재 집계 대상 할 일의 예상 시간 합계 (C32) |
| 실제 시간 | 해당 할 일의 실행 기록에 있는 실제 소요 시간 합계 (C32) |
| 차이 | 실제 시간 − 예상 시간, 빈 합계는 0 (C32) |

- 지표를 클릭하면 계산에 기여한 기록을 확인할 수 있어야 한다. (C83)
- 회고에서 정한 개선 한 가지를 다음 계획으로 이어간다. (C33)

## 실제 서버 DB와 계약

- 계획·할 일·실행 기록·돌아보기 자료를 실제 서버 DB에 저장한다. (C34) 실제 테이블 이름과 구조는 구현 후 계약 파일에 기록한다.
- 새로고침 뒤 ID·날짜·값·단위를 유지한다. (C35)
- 전체 자료를 파일 하나로 내보낸다. (C36)
- 실제 DB 테이블·필드·관계·날짜 규칙을 `contracts/pds-schema-v2.json`에 기록한다.
- 실제 구현을 확인하기 전 DB 구조를 추정한 계약 파일을 작성하지 않는다.
- T06 제출 기준의 실제 소문자 전체 커밋 고정 URL을 보존한다. T07은 이 상태에서 인증을 추가한다.

## 실제 사용과 공개 안내

- 사용자 본인의 실제 계획 1개 이상, 할 일 5개 이상, 실행 기록 3개 이상을 사용한다.
- See가 모두 0인 상태를 실제 사용 근거로 삼지 않는다. (C78~C81)
- T06에는 로그인 기능을 만들지 않는다. 공개해도 되는 본인 내용만 입력한다.
- 첫 화면에 다음 안내를 그대로 표시한다. (C82)

## 입력 안전성과 비밀값

- 저장한 스크립트 모양의 문자열은 문자 그대로 표시하며 실행하지 않는다. (C57)
- 브라우저·빌드·네트워크·콘솔·Git에 비밀값이 드러나지 않아야 한다. (C58)

## 제출과 검증

- 결과물 URL과 소스 URL은 모두 필수이며 파일은 선택이다.
- 모든 제출 결과물·소스 URL은 인증 없이 새 시크릿 창에서 열려야 한다. (C01)
- 소스 URL은 실제 확인한 40자리 또는 64자리 소문자 전체 커밋의 `/commit/FULL_COMMIT` 주소로 작성한다. 별도 해시 입력란은 없다.
- 확인 4항목은 `어디로 가나요`, `무엇을 하나요(3단계 이내)`, `무엇이 보이면 통과`, `안 될 때`를 유지한다. (C59)
- 판단 3항목은 `AI에게 맡긴 일`, `내가 판단한 일`, `AI 말을 안 들은 일`을 유지한다. (C60)
- 실제 검사·사용자 판단·완료 기록을 만들어 쓰지 않는다. 준비 상태는 `docs/PREPARATION.md`, 제출 문안은 `docs/SUBMISSION.md`에 관리한다.

## T06 → T07 보존 조건

T06의 실제 기준 커밋·공개 결과물 URL·실제 DB 구조와 날짜 규칙·전체 내보내기·사용자 판단·검증 근거를 보존한다.

공통 가이드에 따르면 T07은 T06에 인증을 추가하며 서버가 타인의 자료 요청을 거절하는 것을 성공·거절 요청/응답으로 입증한다. 실제 5일 기록에서는 질문·지표·단위·계산 규칙을 유지하고 3일차 전에 계획 규칙을 한 번 바꾼다. T07 설명서 6항목 등 후속 과제의 세부 내용은 해당 최신 화면에서 확정한다.
